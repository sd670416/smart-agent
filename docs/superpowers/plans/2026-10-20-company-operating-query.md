# 自持公司经营智能查询

日期：2026-10-20。状态：已实现，专项与相关完整回归通过，待人工验收。未启动应用、未提交、未切分支。

## 已确认范围

从公司经营组合分析迁入独立查询，不恢复“看板”作为通用业务入口。不包含同比、环比、自定义两组比较或来源单据下钻。

| 指标 | 来源与计算 | 所需权限 |
| --- | --- | --- |
| 项目数量 | 当前可见、审批完成项目按所属自持公司分组计数 | 项目菜单 |
| 施工合同金额 | 所选项目中审批完成、登记类别1的施工合同最终金额，乙方必须为该项目所属自持公司 | 项目菜单 |
| 已收项目款 | 所选项目审批完成回款登记及其他收入登记的到账金额之和 | 项目菜单及两类收入菜单 |
| 开票申请金额 | 所选项目审批完成开票申请主单的本次申请金额，不是实际开票额 | 项目菜单及开票申请菜单 |
| 全部指标 | 上述四项并列，任何来源无权限则不返回不完整总值 | 上述权限并集 |

公司使用项目的 `company_id`，不是联营单位或合同任意乙方。原统计依据：`BusBoardCompanyOperatingStatusServiceImpl` 公司经营分组段。新增公司审批完成约束是统一非审批业务限制，原看板没有显式设置该条件，不为追求数值相等而放宽。

## 查询与安全边界

- `companyOperating.query` / `COMPANY_OPERATING`：公司汇总、项目分页明细及公司精确名称定位。公司汇总不受项目明细分页影响。
- 只支持项目创建日期选择项目后的当前累计数据；日期范围包含结束日。未确定日期含义先使用 `companyOperating.clarifyDate`。
- 租户只取签名可信上下文；请求项目范围与当前可见范围求交。空范围返回空，禁止扩大范围。
- 公司、项目、来源单据审批完成且未删除；项目排除状态1、3、10。无公司或无有效公司档案的项目不进入公司统计。
- 各指标动态生成独立来源 SQL；查询项目数不读取合同、财务表。先按项目聚合每个来源再关联，避免多对多重复累计。
- 缺少审批单据金额时提示数据不完整，不默认为零；无来源单据的项目金额可为零。
- 同名公司按名称精确定位并让用户按公司编号选择，保存原查询条件；公司、项目引用只用于定位，每轮接口重新校验。
- 保存上次查询条件和公司/项目引用以理解序号与翻页，不复用历史金额。实际结果交回模型生成中文业务表格，技术字段不出现在正文。
- 当前会话中的公司序号+指标追问继续公司域；明确改查项目列表、施工合同列表或待办则切换相应业务域。细粒度指标权限由实际工具及接口最终校验。

## 启动与测试

重启 smart-boot、smart-agent；smart-web 未修改，无需重新构建。无需新建菜单或执行数据库迁移。需确认原项目、两类收入和开票申请菜单授权。

1. “按自持公司统计项目数量”：只应显示当前可见且符合审批/项目状态限制的项目，不读取财务金额。
2. “查看各自持公司经营情况”：全权限账号应显示公司、项目数、施工合同金额、已收项目款及开票申请金额。
3. “查看第一家公司的项目明细，每页5条”，再问“下一页”：保持公司、指标和日期范围，每轮重新查询。
4. “第一家公司的施工合同金额呢”：保持公司统计，合同乙方为该公司；不能变成全项目合同总额。
5. “2026年1月各自持公司的已收项目款”：应先确认日期含义；选择项目创建日期后查询这些项目的当前累计收款。
6. 同名公司按编号选择后继续原问题，不循环追问；不存在的公司应明确无匹配数据。
7. 只授权项目的账号可问项目数和施工合同金额；问全部指标应提示对应公司经营指标权限不足，不能返回部分财务数据。
8. “改查项目列表”“查我的待办”：应切换正确业务，审批查询不套用公司经营限制。

本批不代表整个迁移已验收。施工进度专项回归和人工验收、其他批次人工验收及未开放的比较、来源下钻仍需后续处理。
