# 其他付款申请独立智能查询

日期：2026-10-16。状态：已实现，待人工验收。

## 本批范围

其他付款申请作为独立业务来源接入，不复用普通付款申请的数据。支持申请单列表、付款明细、申请单数、明细条数和本次付款金额全量合计。结果交回模型组织中文业务答复，每轮事实查询重新调用接口。

支持项目ID/编号/精确名称定位、用户明确要求的项目名称包含匹配、申请单号、申请单ID、日期区间和分页；同名项目及日期含义不明确时先确认。列表序号只帮助定位真实单据ID，不复用历史金额；切换待办、已办、我发起时仍走审批查询。

不包含普通付款申请、项目报销、退货退款、实际总付款、垫资利润和同比比较。本批不改前端页面、数据库结构或原业务接口。

## 源码核对与字段口径

| 项目 | 原来源及本批实现 |
| --- | --- |
| 原页面 | `smart-web/src/views/finance/bus-finance-other-payment-request/components/form.vue` |
| 原接口 | `/finance/busFinanceOtherPaymentRequest/page`、`get`，原功能保持不变 |
| 主单 | `bus_finance_other_payment_request`，申请单号、项目、创建日期、审批状态 |
| 明细 | `bus_finance_other_payment_request_ref`，按申请单及租户关联 |
| 本次付款金额 | 明细 `current_payment_value` 相加；不使用主单累计金额替代，不累加当前页 |
| 付款类型 | `sys_dict` 的 `bus_finance_other_payment_request_type` 父子字典及当前租户 |
| 二级科目 | 明细 `sub_account_no` 对应科目编号，而非科目ID；同时匹配 `budget_type`、租户和未删除状态，输出 `sub_account_name` |
| 明细展示 | 付款类型、二级科目中文名称、本次付款金额、实际付款时间、备注；没有合同关联，不套用合同模板 |
| 不输出 | 收款银行、银行卡号、收款账户、附件及回单文件信息 |

## 日期与金额

| 日期维度 | 筛选方式 |
| --- | --- |
| 申请创建日期 `createDate` | 先选主单，再统计全部关联明细 |
| 项目创建日期 `projectCreateDate` | 先选项目，再统计符合条件主单的全部明细 |
| 实际付款时间 `paymentDate` | 先筛选子表付款时间，再计算主单金额、明细数和汇总；主单数为有匹配明细的申请单数 |

日期结束日包含全天，实际实现为小于次日零点。实际付款时间为空的明细不计入该日期区间，但其他日期维度下仍可查询其申请金额。不能将付款申请金额直接称作全部实际支出。

同一申请两条明细分别在1月31日付100.01元、2月1日付20.02元：按1月付款时间查，列表/汇总均只显示100.01元、1张申请、1条明细；按申请创建日期查询则可显示整单120.03元。

明细金额缺失及非日期筛选下主单无明细，拒绝输出貌似完整的零金额；无匹配记录返回精确零。主单列表先预聚合明细再分页，汇总不依赖当前页。

## 权限与链路

- 独立叶子菜单：`/finance/bus-finance-other-payment-request` 或组件 `finance/bus-finance-other-payment-request/index`，支持多层菜单遍历。
- 可信权限：`menu:finance:other-payment-request`。财务父菜单、看板或普通付款申请权限不能替代；system账号直接授权，无需配置角色。
- 内部链路：`otherPaymentRequest.query` → `/internal/ai/tools/other-payment-request-query` → 独立查询服务；日期确认使用 `otherPaymentRequest.clarifyDate`。
- 接口验证可信上下文并覆盖模型提供的租户，项目范围与当前可信可见项目取交集；空范围不访问数据库。
- 主单、项目均仅审批完成，排除已删除及项目状态1/3/10；原审批查询不受这项业务限制影响。

## 人工验收

需重启 **smart-boot和smart-agent**；smart-web无变更。不启动服务、不连接业务数据库，留给用户验证。

| 问法/操作 | 预期 |
| --- | --- |
| 查询其他付款申请列表 | 授权范围内审批完成申请；中文表格 |
| 合计多少 | 实时重查全量单数、明细数和本次金额，不只统计当前页 |
| 看第一单的付款明细 | 按上次本域列表真实ID重新查询，不出现合同字段或银行信息 |
| 按实际付款时间查询2026年1月其他付款申请金额 | 仅统计1月有付款时间的明细，不包含同单2月金额 |
| 接着问“看这些付款明细” | 保持已确认的日期维度与区间，重新查询 |
| 查询2026年1月其他付款申请 | 提供申请创建日期、项目创建日期、实际付款时间供确认 |
| 查询付款申请列表 | 切换普通付款申请，不继续其他付款来源 |
| 查询其他付款申请待办 | 切换审批查询 |
| 无其他付款菜单账号查询 | 返回针对其他付款申请的友好权限提示，不借其他权限查询 |

对账需保持审批状态、项目及日期维度一致；按付款时间筛选后的主单金额是匹配明细小计，不等于原页面不筛子表时整单金额。
