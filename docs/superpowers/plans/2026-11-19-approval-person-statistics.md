## 计算口径

| 指标 | 规则 |
| --- | --- |
| 当前待办数量 | 原待办接口按实际受理人员查询，按任务计数，不按流程去重 |
| 待办平均等待时长 | 当前时刻减任务创建时间，所有人员使用同一统计时刻 |
| 已办平均处理时长 | 任务结束减任务开始时间，按任务ID去重，不是实际工作工时 |

已办使用现有已办接口范围和过滤条件，并仅计算办理、退回、跳转、终止、关闭等结束任务的操作，排除转办、委托、加减签等中间操作。缺失或逆序时间不参与平均值；有效样本数单独返回，无样本为null，不冒充0。

processedFrom / processedTo 按已办完成时间筛选；日期上限含当天，精确时间上限不含该时刻，使用 Asia/Shanghai。未指定范围则使用全部可用已办记录。当前待办不受已办时间范围影响。

为兼容既有查询，未传 personKeywords 继续原列表/聚合逻辑；传入时不能混用 personKeyword、filter、select、groupBy、aggregations、orderBy、processType。人员模式返回 groups 和统计时刻，不返回业务单据列表。

保留现有内存统计保护：单人待办或已办源记录超过10000条，以及源记录不完整时，拒绝给出统计，避免以截断数据冒充全部。日期筛选目前在取全后的统计阶段执行，不能用于绕过此源记录上限。

## 人工验证

重启 smart-boot 和 smart-agent，Web无需更新。

1. 使用有指定人员查询权限的账号，询问“查询张三、李四当前待办数量、平均等待时长和已办平均处理时长”。替换为实际姓名。
2. 对照首页按人员查看的待办任务数；三项按人员逐行显示，等待与处理时长分别列出。
3. 追问“已办平均处理时长只看2026年11月1日至11月19日”，核对实时工具调用携带原人员名单和完成时间范围，当前待办数量不因该日期范围减少。
4. 查询零待办或无已办人员：待办为0，无时间样本显示暂无数据。
5. 同名人员先确认账号，确认后重查；普通账号无指定人员权限时应拒绝统计。
6. 改查“我的待办”，核对原列表能力；再次询问人员统计应实时查询。
