# 项目付款与垫资自定义两组比较

日期：2026-10-23。用户已确认范围；实现及定向验证完成，全量回归与审查中，未人工验收。

## 范围和计算

- 仅自定义两组当前累计比较，双方指标必须相同：累计付款、净付款或项目垫资。两组分别按项目、名称包含条件或项目创建日期选择范围。
- 累计付款=付款申请+其他付款申请+项目报销；净付款=累计付款-项目仓材料退货退款；垫资逐项目计算max(净付款-已收项目款,0)后汇总，不能跨项目抵消。
- 返回项目数量与所选指标相关的来源分项、合计、第一组减第二组差额及增长率。第二组为零时增长率不可计算；负数时保留结果并提示结合收支调整理解。
- 复用既有查询SQL与审批限制，不新增合并公式；两组在只读可重复读事务中取数，均按全量数据汇总，不累计分页金额。
- 日期只按项目创建范围选项目后的当前累计数据，不代表期间收支或历史余额；同比环比尚不支持，日期含义不明先确认。
- 每组分别限制可信租户和当前可见项目；按指标校验3/4/6类来源菜单。只取审批完成业务与项目，排除项目状态1/3/10。无业务记录项目金额为零，缺有效金额则中止完整比较，不能静默当零。
- 同名项目先确认并恢复另一组条件；按组查询项目列表与分项、翻页及再次比较必须重新调用接口；历史仅保留筛选与真实定位，不复用历史金额。
- 不启动应用、不连接业务数据库、不改数据库或Web，不切换分支或提交已有改动。

4. 项目同名先选择，所选组改变后另一组不丢失；日期确认选择不限定日期后两组均清除旧日期。
5. 一个项目垫资80、另一个盈余150时，同组垫资合计仍为80，不能为0或负数；第二组为零时增长率不能显示0%。
6. 只有三类付款菜单可比较累计付款；净付款另需退款菜单，垫资另需两类收入菜单。缺必要菜单不得返回部分完整金额，也不提示无权查看项目。
7. 当前账号项目范围收窄后再次提问应使用新权限；缺有效金额应提示核实金额，不伪造合计。
8. “去年年底垫资同比”：说明暂不支持历史余额，不能拿当前累计代替；组别或比较指标不明先追问。
