# 项目报销单据详情与多轮下钻

日期：2026-10-23。状态：开发及自动验证完成，待人工验收。

## 支持范围

- 复用项目报销查询，不新增业务域。detail不传requestId为原报销单列表；传真实报销主单requestId为单据自身详情，合法旧页码归一为1。items保持原分页能力。
- 对照完整版与简化版原报销表单，详情补充报销人、报销事由。报销人按当前同租户未删除用户回显姓名，不是历史人员快照；姓名不可用显示“未维护或不可用”，不展示原始用户编码。
- 主单报销事由与费用明细备注分别展示；费用明细保留所属项目、报销类型、二级科目、费用金额和备注，不使用其他付款或普通付款模板。
- 列表序号只用于定位真实主单；items的itemId不能作为主单ID。明细翻页和返回主单保留主单ID、项目、单号、日期；无明确主单或指代存在歧义时追问。
- 每轮重新调用接口，历史只提供意图和定位；查询结果仍交回模型生成中文业务回复。summary须清除单笔requestId，服务端和Agent均拒绝summary携带单笔ID，避免误把单笔当全量。

## 金额、日期与权限

一张报销单可跨多个项目。先按可信项目范围、项目及日期条件筛选费用，再聚合报销单。列表、详情、汇总与比较均不使用主表整单金额；单笔详情也不是对当前一页明细求和。

| 日期条件 | 含义 |
| --- | --- |
| 单据创建日期 | 选择创建期间内的报销单，费用仍限制在当前可见及匹配项目内 |
| 报销日期 | 选择主单报销日期期间，不是实际付款日期 |
| 项目创建日期 | 只选创建期间内项目对应的费用；不能包含同单其他项目费用 |

范围含结束日全天。返回主单不能自动移除日期或项目条件。报销金额不等于实际付款、扣除备用金后的实付金额或个人累计报销。缺失可见费用金额拒绝形成貌似完整的结果，不默认为零。

沿用项目报销叶菜单、可信租户、当前可见项目；主单及项目未删除、审批完成，项目排除1/3/10。空项目范围无结果，主单ID、单号、日期与项目条件同时生效；无结果不能清除ID扩大查询。用户名称关联显式限制同租户和未删除。

本批不接入个人报销、个人累计、备用金抵扣、发票明细、银行账户、收款人、附件和付款回单，不更改比较公式或审批详情模板。待办、已办、我发起仍走审批查询。

## 重启与人工验收

重启smart-boot、smart-agent。smart-web和数据库无需更新；本批不启动项目、不连接业务数据库。

1. “查询项目报销列表，第2页”。再问“查看第一单详情”，核对同一报销单号、报销人、报销事由；不能因列表旧页码为空。
2. 选择有多条费用的报销单：“查看这单费用明细，每页1条”“下一页”“返回这张报销单详情”。应保持同一主单，明细正常翻页，返回详情不受旧页码影响，金额为当前范围完整小计。
3. “按报销日期查询2026年2月2日项目报销”，再查看某单详情、明细及返回主单，日期和项目条件始终保留。可替换为实际有数据的日期。
4. 用只能查看多项目报销单中一个项目的账号验证：详情与明细只含当前可见费用，不展示其他项目、主表整单金额、个人累计或银行信息。
5. 按项目创建日期选择项目后查看跨项目报销单，再返回主单，仍只含匹配项目费用，不能扩大为整单。
6. 修改费用金额、主单审批状态或账号可见项目后再次查询，应实时反映；无菜单账号应提示项目报销权限不足。
7. “查询所有项目报销合计”应清除单笔ID并实时汇总；日期等范围按本轮意图保留或明确修改，有歧义先确认。
8. “查询项目报销待办”应切换审批域，不把审批完成的报销业务单据作为待办返回。
