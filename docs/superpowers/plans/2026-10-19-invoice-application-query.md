# 开票申请独立智能查询

日期：2026-10-19。状态：已实现，待人工验收；未启动应用。

## 范围与口径

- 来源：开票申请业务页面 `finance/bus-finance-invoice-application/index`（含简化版本），不是开票登记页面。
- `invoiceApplication.query`：主单分页列表、真实申请单ID限定的主单详情、申请单数及申请金额全量汇总；`items` 查看指定申请下登记的发票明细。
- 仅可信租户、可见项目范围内未删除且审批完成的申请；项目同样审批完成且未删除，排除项目状态1、3、10。
- 金额只累加主单本次开票申请金额，不使用历史累计金额，不因连接发票明细重复计算。审批完成主单缺金额时拒绝提供不完整合计。
- 开票申请金额不等于实际已开票金额。下挂发票记录仅展示登记明细，不宣称为已核验的实际开票统计。
- 日期支持申请创建日期及项目创建日期，结束日含全天。日期歧义先追问，相对日期先获取当前时间。
- 不含公司经营综合统计、同比、环比或自定义两组比较，不能由模型自行拆查替代。

## 权限与交互

- 独立权限 `menu:finance:invoice-application`，递归识别开票申请叶子菜单；财务父菜单、看板菜单、开票登记菜单均不能代替。system账号直接授权，不依赖角色。
- 内部接口 `/internal/ai/tools/invoice-application-query` 沿用可信签名上下文；覆盖租户并与可信项目范围相交。SQL显式同租户关联与范围过滤，不依赖全局租户插件配置。
- 主单及发票明细均保留权限边界，传申请ID不能绕过项目与租户检查。
- 每轮事实查询实时调用工具，查询结果交回模型按中文列名回答。序号追问使用当前列表可信真实申请单ID，不使用序号当ID。
- 开票申请待办、已办、我发起及流程问题仍由审批工具处理。无权提示使用“开票申请”业务名称。

## 如何验收

重新编译并重启 smart-boot、smart-agent；smart-web无变更，不需重启前端。

1. “查询开票申请列表”：应显示申请编号、项目名称、申请金额、开票内容、创建日期、审批状态。
2. “开票申请总共有多少单，申请金额合计多少”：应重新查询全量汇总，不相加当前页。
3. “查看第一单的详情”，接着“查看这一单登记的发票明细”：应分别实时查对应真实申请单，不能切换为项目档案或审批待办。
4. “2026年1月开票申请金额”：应确认按申请创建日期还是项目创建日期；明确选择后再查询。
5. “查询开票申请待办”：应切换审批查询，不使用本工具代替。
6. 使用无开票申请菜单账号、不同租户及不同可见项目范围对照：不得越权；申请金额应与相同范围审批完成主单相符。
