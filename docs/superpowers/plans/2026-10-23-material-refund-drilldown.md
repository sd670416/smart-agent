# 材料退货退款单据详情与多轮下钻

日期：2026-10-23。状态：开发及自动验证完成，待人工验收。

## 支持范围

- 复用材料退货退款查询。detail不传requestId仍为列表；传真实主单requestId为单据自身详情，合法旧页码归一为1。items保持材料明细分页能力，itemId不能作为主单ID。
- 对照原材料退货表单，详情补充采购组织（如有）、退货出库仓库、退货原因、退货单备注。主单备注与明细备注分别展示。
- 原页面采购组织仅在公司仓模式显示；项目仓单据可能未填写，不能从所属组织、项目经理或项目名称猜测采购组织。只回显主单已有采购组织引用，空值显示“未填写”，名称已删除或不可用时不暴露原始ID。
- 仓库名称优先使用单据保存的名称快照；快照为空时查询当前同租户未删除仓库名称。采购组织名称也仅从同租户未删除公司获取。采购组织当前名称及仓库回退名称不是登记时的历史快照。
- 列表序号定位真实主单后逐轮实时重查；材料明细翻页与返回主单保留主单ID、项目、单号和日期。主单指代不明确先追问，不能用明细序号猜主单。
- summary拒绝携带单笔requestId，防止由单笔转全量时误继承ID；单笔金额以该单当前匹配全部明细计算，不能累加一页明细代替。

## 日期与金额

| 日期条件 | 金额含义 |
| --- | --- |
| 单据创建日期 | 选择该期间创建的单据，累计其符合权限的全部材料明细本次金额 |
| 项目创建日期 | 选择该期间创建的项目，累计匹配单据材料明细本次金额 |
| 材料退货时间 | 先筛选区间内材料明细，再聚合单据；详情也是期间小计，不是整单金额 |

按退货时间查询的列表、详情和明细使用“筛选期间退货退款金额（元）”；主单明细数量也标明筛选期间。appliedFilters用amountScope区分MATCHED_RETURN_ITEMS和ALL_DOCUMENT_ITEMS；汇总与比较指标标签、计算公式保持原行为。

例如同单1月100.01元、2月20.02元：按1月退货时间查单据详情及返回主单仍为100.01元，不能变成120.03元。只有用户明确取消退货日期条件时才改查整单；意图不清先追问。区间包含结束日全天，无退货时间明细不计入期间，无匹配明细返回空结果。缺失可见金额拒绝形成貌似完整的结果，不默认为零。

只累计子表本次退货退款金额，不输出主表历史累计付款或退款金额，不称“已到账退款”。不计算跨材料不同单位的数量总和。

## 权限与边界

- 沿用材料退货叶菜单、可信租户与当前可见项目范围；主单与项目未删除且审批完成，项目排除1/3/10。
- 仍仅退货退款type=2、项目仓purchase_type=1；不因组织名称或仓库引用扩大到公司仓或仅退货。
- 主单ID、单号、项目及日期同时生效，空项目范围无结果，不能清除ID或筛选降级重试。
- 不接入附件、历史累计、银行、实际到账查询、审批操作或原业务页面改造。

## 重启与验收

重启smart-boot、smart-agent；smart-web和数据库无需更新。本轮不启动项目、不连接业务数据库。

1. “查询材料退货退款列表，第2页”。再问“查看第一单详情”，核对单号、退货出库仓库、退货原因、退货单备注；采购组织未填写时不能伪造组织。
2. 选有多条明细的记录：“查看这单材料明细，每页1条”“下一页”“返回这张退货退款单详情”。核对同一主单、不同明细，返回详情不受明细旧页码影响，主单备注不混为材料备注。
3. “按退货时间查询2026年1月材料退货退款”，然后查看某单详情、明细、返回主单。应始终仅为1月匹配材料金额，标明筛选期间；可替换为实际有数据的日期。
4. 明确说“这单不限定退货时间，查看整单详情”，核对仍是同一主单与项目，重新汇总其全部明细，而非当前页金额。
5. 用项目受限及无菜单账号测试不可越权；原页面仅退货、公司仓单据不应进入结果。
6. 修改金额、审批状态或可见项目后再查询，结果必须实时变化；金额不能读取主表历史累计值，也不能称已到账。
7. “查询所有材料退货退款合计”，应清除单笔ID并实时全量汇总；是否保留日期遵循本轮意图，有歧义先确认。
8. “查询材料退货退款待办”，应切换审批域，不把业务单据列表作为待办。
