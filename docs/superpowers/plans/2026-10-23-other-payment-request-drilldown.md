# 其他付款申请单据详情与多轮下钻

日期：2026-10-23。状态：开发及自动验证完成，待人工验收。

## 支持范围

- 复用其他付款申请查询，不新建业务域，不使用普通付款申请替代。detail无requestId仍为列表；带真实申请主单requestId为自身详情，页码归一为1，避免继承列表或明细旧页码。
- 按原表单补充所属组织、项目经理、项目性质、申请单备注；项目关联信息为当前数据，不是申请创建时的历史人员或组织快照。项目性质按bus_project_nature中文回显，名称不可用不展示原始编码。
- 明细继续展示付款类型、二级科目、本次付款金额、实际付款时间和明细备注。申请单备注与明细备注区分；本业务不套用合同模板，不添加合同字段。
- items翻页保留真实主单ID、项目、单号和日期；返回申请单使用detail和同一requestId。itemId不是申请单ID，历史结果仅用于定位，每轮调用接口实时取数。
- summary不能携带单笔requestId，避免由单笔转全量汇总时误保留主单ID。单笔金额使用该单详情的完整匹配明细聚合，不以单页金额代替。

## 日期和金额

| 日期条件 | 单笔详情、列表及汇总金额含义 |
| --- | --- |
| 申请创建日期 | 按主单创建期间选择申请，取匹配申请的全部明细本次金额 |
| 项目创建日期 | 按项目创建期间选择项目，取匹配申请的全部明细本次金额 |
| 实际付款时间 | 先筛区间内付款明细，再聚合；只含匹配明细，不是整单金额 |

实际付款时间范围包含结束日全天，无付款时间的明细不计入该范围。单笔详情、列表及明细的金额标签提示“筛选期间”，主单明细数也提示“筛选期间”；汇总/比较保持原指标名称与公式，以appliedFilters中的amountScope区分MATCHED_PAYMENT_ITEMS和ALL_DOCUMENT_ITEMS，并向模型明确范围。

例如同一申请1月付100.01元、2月付20.02元：按1月付款时间查详情和明细仍为100.01元，不因“返回主单”变为120.03元。只有用户明确改查不限定付款日期的整单时才移除付款日期范围；意图不明确先追问，不能静默扩大范围。无匹配明细返回无结果，缺失匹配金额拒绝形成貌似完整的零值。

## 权限与边界

- 沿用其他付款申请叶菜单、可信签名租户、当前可见项目范围；普通付款菜单、财务父菜单和看板权限不可替代。
- 主单和项目未删除且审批完成，排除项目状态1/3/10；当前范围为空不查询数据库。用户、部门及字典关联显式同租户，已删除名称不可用。
- 单据ID、项目、单号、日期条件同时生效，无结果不能移除ID重试。待办、已办、我发起及流程仍使用审批业务域。
- 不返回银行、收款账户、银行卡号、附件和回单；不接入审批操作，不修改原表单或审批详情模板。

## 重启与人工验收

重启smart-boot、smart-agent。smart-web及数据库无需更新；本轮未启动项目、未连接业务数据库。

1. “查询其他付款申请列表，第2页，每页2条”。
2. “查看第1笔的申请单详情”。核对主单号、所属组织、项目经理、项目性质、申请单备注，不受旧页码影响。
3. 选择有多条明细的记录：“看这笔的付款明细，每页1条”；再问“下一页”“返回这笔申请单详情”。核对同一主单、不同明细，主单备注不混入明细备注，每轮实时查询。
4. “按实际付款时间查询2026年1月其他付款申请”；再查其中一笔详情及明细、返回主单。始终只含1月匹配明细，金额标明筛选期间，不能自动包含2月。
5. 明确说“这笔不限定付款日期，查看整单详情”。核对仍保留同一主单和项目，金额改为全部明细本次金额，而非当前页小计。
6. “查询所有其他付款申请合计”。清除单笔ID后重新全量聚合；是否保留日期应遵从本轮明确条件，歧义先确认。
7. 无菜单和项目受限账号验证不可越权；修改主单审批状态、金额后再次查询，不使用历史结果。
8. “查询其他付款申请待办”。应切换审批业务域，不能把业务档案冒充待办。
