# 付款申请比较实施与验收

日期：2026-10-21。状态：开发与自动回归完成，待人工验收。

## 范围

- 在付款申请业务域新增 paymentRequest.compare，不恢复看板业务域。
- YOY同比、MOM环比、CUSTOM自定义两组；比较申请单数、付款明细条数、本次付款金额。
- createDate按申请创建期间统计；projectCreateDate按创建期间选择项目后，统计这些项目当前审批完成的付款申请。后者不是当期实际支付。
- 日期含义不明确先确认；比较期间缺失可选择本月、本季度、今年截至今天，也可补充具体日期。每组必须明确日期维度与起止日期，暂不支持无日期的全历史比较，遗漏日期不能自动退成全历史统计。
- 相对日期先取当前时间，自动比较由Boot公共日期逻辑推导上期，不接受模型覆盖自动对比期。支持整月、季度、年度及部分期间；任意日期同比使用RANGE，环比不接受任意区间。
- 同名项目分别确认本期或对比期；确认恢复两组原条件，每轮实时查询，历史只用于理解条件。
- 本次不接入单号/单据ID比较、其他付款、报销、退款、垫资或利润比较；金额不是实际银行支付。

## 实现

- Agent：比较工具、参数校验、模型说明、日期/期间追问、项目确认恢复、结果回交模型、业务工具超时配置。
- 内部接口：POST /internal/ai/tools/payment-request-compare，使用接口实际路径生成可信签名；分别校验两组可见项目。
- Boot：校验付款申请菜单；覆盖两组可信租户并与当前项目范围取交集。自动对比期继承受限后的本期范围。
- 两组强制使用summary复用原全量汇总，审批完成和项目排除状态不变；不累加单页明细，不更改原金额公式。
- 复用QueryComparisonSupport计算本期减对比期及增长率；基准零不计算比例，任何组失败不返回部分比较。
- 无数据库或Web变更，未启动应用。

## 人工验收

重启 smart-boot 和 smart-agent，前端无需更新。

| 问法/操作 | 预期 |
| --- | --- |
| 按申请创建日期，比较2026年9月付款申请同比 | 对比2025年9月；显示两组日期、数量、金额、差额、增长率 |
| 按申请创建日期，比较2026年3月付款申请环比 | 对比2026年2月1日至28日，而不是截成相同天数 |
| 按申请创建日期，比较今年截至今天付款申请同比 | 先取当前时间，本年已过期间对比上年同期 |
| 比较付款申请同比 | 缺日期含义或比较期间先追问，不猜测 |
| 按申请创建日期，比较项目甲2026年9月和项目乙2026年8月的付款申请 | 两组独立项目范围及日期，同名先确认 |
| 比较后追问“再查一次” | 当前轮重新调用比较工具，不引用上轮金额 |
| 对比期金额为零 | 显示金额差额，增长率无法计算，不返回无穷或伪造100% |
| 无付款申请菜单/项目范围变化 | 权限由当前可信接口控制，不泄露另一组数据 |

核对原付款申请列表使用相同项目、审批完成状态与日期维度，比较全量金额，不以分页相加代替；业务回复不得暴露工具名或技术字段。
