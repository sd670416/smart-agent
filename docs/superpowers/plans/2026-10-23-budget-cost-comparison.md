# 预算成本自定义两组比较

日期：2026-10-23。开发及自动验证完成，待人工验收；不代表人工验收完成。

## 范围

- 自定义两组项目的当前项目数量、合并预算成本、差额和增长率。
- 复用审批完成预算编制、新增预算和最新有效变更的既有合并规则，不累加全部版本。
- 日期仅按项目创建范围选择项目，不是期间新增预算、历史预算快照；不支持同比或环比。
- 两组分别校验目标成本档案菜单、可信租户、可见项目与统一审批及项目状态限制。
- 缺失有效行金额不能当零；无预算记录项目保留且预算为零。
- 按组查看项目列表，再按真实项目定位预算明细；所有事实查询实时取数，指代不清先确认。
- 不启动应用、不连接业务数据库、不改Web或数据库、不提交或切换分支。

## 实现与验证

- 新增预算成本两组比较能力，复用预算查询服务与既有合并SQL。服务端在只读可重复读事务中获取两组，均为全量汇总，不累计分页数据。
- 差额为第一组减第二组；增长率以第二组为基数。第二组为零时不可计算，为负数时保留数学结果并提示结合预算调整理解。
- 项目同名选择后恢复两组真实条件；不限定日期时清除两组旧日期。比较行不能当成项目列表序号；按组重新查询项目列表，再定位预算明细。
- 自动验证覆盖真实MyBatis XML、H2 MySQL模式和租户拦截器；未连接业务MySQL，不能替代实际业务数据对账。
- Agent最终全量834项通过，失败、错误及跳过均为0。初次全量有一项既有ToolExecutorTest的50毫秒超时竞争（预期大结果超限），单独复跑及全量复跑均通过，未更改该测试或执行器。
- Boot最终23项通过（预算SQL16、接口7），失败、错误及跳过均为0；含最新变更预算重算、无预算项目、日期全天、缺金额、负数基数、空组、非法类型/模式/日期维度/租户及双组权限。
- 复核命令：Agent `mvn -o -q test`；Boot使用JDK8执行 `mvn -o -q -pl smart-ai,smart-business/smart-budget -am test -Dtest=BudgetCostSqlTest,AiBudgetCostToolControllerTest -Dsurefire.failIfNoSpecifiedTests=false -DfailIfNoTests=false`。日志分别为 `budget-compare-agent-final-recheck.log`、`budget-compare-boot-final-tests.log`，两条命令退出码均为0；两仓库diff检查通过。
- 独立只读审查无确定的待修复缺陷。真实模型对组别的理解、实际MySQL及事务集成行为仍需人工或环境验收；脚本化模型对话测试不代表真实模型验收。

## 重启与人工测试

重新编译并重启smart-boot和smart-agent；smart-web和数据库无变更。本批未启动应用。

1. “比较甲项目和乙项目当前预算成本”：使用两个真实项目，核对项目数量、已审批合并预算、差额及增长率。
2. “查看第二组的项目预算列表” → “看第一项的预算明细” → “下一页”：每轮重新调用查询，保留所选组项目和日期，不查审批待办。
3. “比较2026年1月创建的项目和2月创建的项目当前预算成本”：按创建范围选项目，金额为当前合并预算，不声称期间新增预算或历史快照。
4. 同名项目应先确认；两组不明确时先补充条件。选择不限定日期后，两组参数均不得保留旧日期。
5. 无预算项目预算为零；缺有效金额则提示数据不完整，不返回看似准确的部分比较。第二组为零时增长率显示无法计算。
6. 无目标成本档案菜单不读取预算；项目范围收窄后重新查询应按当前权限执行。同比、环比或历史预算应说明尚未支持，不用当前预算冒充。
