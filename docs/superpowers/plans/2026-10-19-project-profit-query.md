# 项目利润独立智能查询

日期：2026-10-19。用户已确认计算规则与首批范围。状态：自动化回归及独立复查完成，待人工验收。沿用当前分支，不启动应用、不连接业务数据库、不修改前端。

## 已确认公式

| 指标 | 公式 |
| --- | --- |
| 预算利润 | 审批完成、登记类别1施工合同最终金额 - 合并预算成本 |
| 实际收支利润 | 已收项目款 - 净付款 |
| 净付款 | 付款申请 + 其他付款申请 + 项目报销 - 项目仓材料退货退款 |
| 已收项目款 | 回款登记 + 其他收入登记 |
| 预算利润率 | 预算利润 / 施工合同最终金额 × 100% |
| 实际收支利润率 | 实际收支利润 / 已收项目款 × 100% |

退款仅抵减一次净付款，不再从实际利润中二次扣除。利润亏损及负利润率保留，不归零。分母为零时返回空利润率及“暂无法计算”说明，不能显示为0%。百分数保留4位小数，四舍五入。汇总率以汇总利润除以汇总分母，不平均项目百分比。

实际利润只是已审批业务记录的累计收支估算，不是会计核算利润或银行实付、实际到账的保证。上述公式按本轮确认统一，不复制旧柱图二次减退款、亏损率归零的处理；不修改原看板页面。

## 查询与权限

业务域 `PROJECT_PROFIT`，工具 `projectProfit.query`、`projectProfit.clarifyDate`，接口 `/internal/ai/tools/project-profit-query`。

| 参数 | 范围 |
| --- | --- |
| metric=budget | 预算利润、利润率及合同/预算分项；需要项目菜单与目标成本档案菜单，共2类来源权限 |
| metric=actual | 实际收支利润、利润率及六来源分项；需要三类付款、材料退货、两类收入，共6类来源权限 |
| metric=both（默认） | 同时展示预算与实际分项，需上述全部8类来源权限 |
| mode=summary（默认） | 全部匹配项目合计，不受列表页影响 |
| mode=detail | 按项目分页，每项包含计算分项；明确项目后可查看该项目分项 |
| projectId/projectCode/projectName | 使用真实ID、精确编号/名称；同名先确认；仅明确名称包含时允许模糊匹配 |
| dateField | 只支持projectCreateDate，选择项目创建范围后查询这些项目的当前累计利润 |
| page/pageSize | 默认1/20，最大100 |

接口使用可信租户及可见项目交集，不能从请求扩大范围。项目只取审批完成，排除状态1/3/10；所有来源记录只取审批完成且未删除。预算复用最新有效变更合并规则；材料退款仅项目仓退货退款明细。某来源有有效记录但金额缺失时拒绝不完整汇总，无记录时才按零计。

SQL复用预算与付款来源的projectRows片段，金额一次查询取得，不逐项目调用多个接口，也不重复定义预算版本规则。财务模块显式依赖预算模块，确保共享映射加载。共享预算片段内部引用使用完整命名空间，避免跨mapper复用时解析错误。

## 对话行为

每轮实时调用查询工具，结果交回模型按中文列名回复。保存上轮筛选条件和权限内真实项目引用支持追问，历史金额不可作为本轮事实。利润列表后的“看第一个项目”继续利润域；明确“项目档案”可切换项目域。预算/实际指标不明确的同域追问继承上轮指标后校验权限，不能无故要求额外来源权限。

日期不明确时先确认，可按项目创建日期选择项目或不限制日期。结束日包含全天，相对日期先取当前时间；不支持期间利润或历史时点快照。待办、已办、我发起查询仍走审批域。

本批只做汇总、列表和计算分项，不做同比、环比、两组筛选比较或来源单据下钻。预算与实际两列并列不表示已实现期间比较。
