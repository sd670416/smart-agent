## 本批范围

- 项目报销单列表、费用明细、报销单数、费用条数及报销金额汇总。
- 独立工具 `projectReimburse.query`，按财务项目报销叶子菜单和当前可信可见项目授权；不依赖旧看板权限。
- 主单和关联项目均须审批完成，项目排除立项中、立项未通过、关闭（1/3/10）。
- 不包含个人报销、发票、借款抵扣、银行账户、退货退款、同比比较或多来源付款总额。

## 字段和统计边界

| 内容 | 实际来源/行为 |
| --- | --- |
| 日期 | 报销日期 `reimburseDate`、单据创建日期 `createDate`、项目创建日期 `projectCreateDate`；不明确先追问 |
| 项目 | 子表 `bus_finance_project_reimburse_ref.project_id`，不是主单临时项目字段 |
| 金额 | 先按可信项目和条件筛费用行，再汇总子表 `reimburse_amount`；不返回主单整单金额 |
| 单数 | 当前匹配费用行的主单去重计数，费用条数单独计数 |
| 报销类型 | 沿用原表单字典 `bus_finance_other_payment_request_type` |
| 二级科目 | 按 `sub_account_no` + `budget_type=reimburse_type` 关联，限制租户与未删除 |
| 涉及项目 | JSON数组聚合再结构化去重，避免 GROUP_CONCAT 默认长度截断 |

一张报销单可含多个项目。只显示当前有权且满足条件的费用及金额，列表按过滤后的主单分组后分页。空范围返回空列表或零汇总，未完成审批不混入；金额缺失不能默认为零。

每轮事实查询实时调用接口，历史仅用于理解筛选、模块和序号。第一单等引用保留真实单号和当前可见项目ID，权限变化后重新限制；查询结果继续交模型生成业务回复。
