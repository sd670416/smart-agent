# 其他付款申请比较实施与验收

日期：2026-10-21。状态：开发及自动回归完成，待人工验收。

## 已实现范围

- 独立其他付款申请比较工具及内部接口，支持同比、环比、自定义两组比较；不与普通付款申请、报销或退款混用。
- 比较审批完成的申请单数、付款明细条数、本次付款金额；并非银行实际支付总额。
- 日期维度：申请创建日期、项目创建日期、明细实际付款时间。每组必须有明确日期维度及完整起止日，两组维度相同；缺少期间或日期含义不明确先追问，不默认全历史。
- 按实际付款时间先过滤子明细，只汇总期间内金额；同一申请即使多条匹配明细也只计一单，无付款时间明细不纳入期间。
- 同比上年同期；环比上一自然月、季度或年；完整期间比较完整上期，部分期间比较相应已过区间。自动比较不得自行覆盖对比组，自定义比较明确两组条件。
- 两组分别受其他付款菜单、可信租户及当前可见项目范围约束；继续使用原查询的审批和项目状态限制。
- 同名项目按组确认，保留另一组条件；日期和期间选择后恢复原业务查询。每轮实时查询，查询结果交回模型组织业务答复；服务端计算差额与增长率，零基准不计算比例。

## 重启及人工测试

重启 smart-boot、smart-agent。smart-web和数据库本批无需更新。

| 测试问法或操作 | 预期 |
| --- | --- |
| 按实际付款时间比较2026年1月其他付款申请同比 | 展示本期与上年同期的日期、单数、明细数、金额及差额增长率 |
| 按实际付款时间比较2026年3月其他付款申请环比 | 与完整2月比较，不遗漏2月末日 |
| 按申请创建日期比较2026年1月和2月其他付款申请 | 自定义两组，只比较对应期间申请 |
| 比较其他付款申请同比 | 日期含义或期间不明确时先确认，不直接全历史查询 |
| 接着问“再查一次” | 继承已确认条件并实时调用比较，不复述历史数据 |
| 比较两个同名项目的其他付款申请 | 分组确认项目，另一组日期和范围不能丢失 |
| 无其他付款菜单，仅有普通付款菜单账号查询 | 友好提示缺少其他付款查看权限，不借普通付款权限查询 |

对账时保持日期维度、项目范围、审批及项目状态一致。付款日期比较只能与同样筛选子明细后的金额对账，不能直接拿整张申请金额对比。
