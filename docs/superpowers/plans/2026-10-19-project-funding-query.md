# 总付款与项目垫资组合查询

日期：2026-10-19。状态：实现、自动化回归及独立复查完成，待人工验收。沿用现有分支，不修改前端、不启动应用、不连接业务数据库。

## 已确认规则

| 指标 | 计算 | 必需来源菜单 |
| --- | --- | --- |
| 累计付款 | 付款申请明细本次金额 + 其他付款明细本次金额 + 项目报销明细金额 | 三类付款菜单 |
| 净付款 | 累计付款 - 项目仓材料退货退款明细本次金额 | 上述三类及材料退货菜单 |
| 已收项目款 | 回款登记金额 + 其他收入登记金额 | 两类收入菜单，作为垫资来源 |
| 单项目垫资 | max(净付款 - 已收项目款, 0) | 全部六类来源菜单 |
| 垫资合计 | 对每个项目先计算并归零负值，再相加 | 不允许不同项目盈余抵消 |

业务记录只取审批完成；项目只取审批完成并排除状态1、3、10。所有查询受当前可信租户及可见项目交集限制。报销归属以费用明细项目为准，不读取整单中其他项目费用。退款仅type=2、purchase_type=1，不含仅退货、公司仓及主单历史累计金额。

累计付款是审批记录计算值，不声称银行已实际支付。退款不声称实际到账。可见来源金额缺失时拒绝不完整汇总，不能默认为零；没有业务记录的合规可见项目仍保留，金额为零。缺少必要菜单拒绝完整金额，不返回部分金额冒充合计。

## 查询接口与对话

Agent业务域 `PROJECT_FUNDING`，工具 `projectFunding.query`，接口 `/internal/ai/tools/project-funding-query`。

| 参数 | 用途 |
| --- | --- |
| metric | cumulative累计付款、net净付款、funding垫资（默认） |
| mode | summary全范围汇总（默认）、detail项目列表 |
| projectId/projectCode/projectName | 真实ID、编号或名称定位；默认精确定位，同名追问 |
| projectNameMatch | exact默认；用户明确名称包含才允许contains |
| dateField | 仅projectCreateDate项目创建日期 |
| startDate/endDate | 项目创建日期范围，包含结束日全天 |
| page/pageSize | 项目列表分页，默认1/20，最大100 |

日期仅选择项目集合，再累计这些项目的审批完成业务记录，不是区间内收支。用户只说“今年垫资”时先调用 `projectFunding.clarifyDate`，可确认“按项目创建日期筛选”或“不限定日期，查看累计金额”；不支持的期间收支不能自动替换成创建日期。相对日期先取当前时间。

项目级来源金额在单条SQL中分来源聚合后关联项目，避免多源明细连接产生乘积，也不逐项目发起六次接口查询。程序逐项目计算垫资并全量汇总后分页，不能相加当前页。结果交给模型按中文列名组织业务答复，不直出内部代码字段。每轮重新调用；保存条件和当前权限内真实项目引用支持连续追问，不把历史金额当本轮事实。
