# 智能助手问题记录设计

日期：2026-10-14

## 已确认范围

新增“问题记录”管理页面，持久化记录智能助手未完成的用户问题，便于针对性开发。只有记录、检索和详情，不提供跟进状态、指派、处理备注、关闭或解决流程。

页面权限由用户通过现有菜单管理自行配置，不限制为 system 账号，不自动给角色授权。登记菜单及查看权限项，不修改已有权限分配。管理页可查看当前租户内各用户的问题；没有查看权限不能访问列表和详情。

## 收集规则

采用服务端运行结果、模型明确标记和用户反馈三种互补来源，不扫描回答中的某些词语来判断是否失败。

| 来源 | 纳入记录 | 排除 |
| --- | --- | --- |
| 运行终态 | 查询/模型错误、超时、空回答、非法工具参数导致最终失败 | 正常完成、用户取消、权限不足 |
| 模型明确标记 | 当前能力不能完成问题、业务或字段尚不支持 | 正常无数据、正在澄清、尚可调用其他工具完成的问题 |
| 用户反馈 | 当前用户在自己的助手消息上点击“未解决” | 伪造其他用户或其他租户的消息/运行 ID |

同一轮中间工具失败、但最终已完成回答的，不按系统错误自动收集。每轮运行至多一条记录，来源可补充，手动反馈重复提交不新增重复记录。不进行相似问题合并，避免误合并不同上下文。

模型明确标记只能用于记录“尚不支持”的原因，不得改变权限、放宽查询范围或代替正常工具查询。记录失败不能导致原聊天失败；服务端记录脱敏错误并允许排查。

“未解决”按钮在已有聊天消息操作区域增加，反馈接口不要求问题管理页权限，但必须校验当前租户、当前用户及消息/运行归属；问题和回复均从服务端已有会话读取，不能信任前端提交的内容。

## 页面

路由 `/ai/question-record`，组件 `smart-web/src/views/ai/question-record/index.vue`，沿用现有菜单生成路由规则。

列表字段：记录时间、提问用户（可用名称和用户 ID）、原问题、业务模块、来源、原因。支持问题关键字、用户、业务模块、来源、日期范围筛选及分页；默认时间倒序，同时间使用记录 ID 保证稳定排序。

详情展示：原问题、助手回复、原因/安全错误码、发生时间、业务模块，以及 conversationId、runId、traceId；相关上下文仅展示该轮之前必要的消息，工具调用展示安全的工具名称、参数和结果摘要。不得展示该轮之后才发生的会话消息，避免误解现场。

加载、空列表、详情不存在、访问被拒绝和请求失败分别展示对应状态。无跟进类按钮，无删除、批量操作或导出功能。

## 存储与服务边界

`smart-agent` 增加独立问题记录组件与 Flyway 迁移，复用现有 `ai_run`、会话和运行步骤机制。

记录保存 tenantId、userId、conversationId、runId、traceId、原问题及回复快照、业务域、来源、原因码、原因说明、创建时间和事件截止时间。按 tenantId + runId 设置唯一约束，列表建立租户/时间索引。必要上下文受消息数和长度限制，不能复制整段无限增长的会话。记录没有状态字段。

从终态/最终答案路径提交收集事件；独立事务保存，不把收集事务失败传播到聊天。脱敏复用现有安全错误和调试结果处理，禁止复制原始异常栈、密钥、请求签名或完整未裁剪工具数据。

模型侧通过结构化的“能力未支持”标记表达未解决原因，编排层校验对应本轮运行，不使用另一次模型调用来逐条评价所有回答。最终未解决状态才持久化；模型标记不保证识别所有答非所问，用户反馈用于补漏。

`smart-boot` 增加 `/ai/question-records` 网关接口，沿用可信签名转发；列表和详情在网关与 agent 两端校验同一个查看权限码 `aiQuestion:menu`。租户来自可信登录上下文，不接受前端指定租户。

菜单登记脚本只登记页面菜单和“查看”权限项，不插入角色菜单或角色按钮关联。按当前本地数据库实际菜单层级与重复记录核验后登记，不在本功能中调整其他菜单。

历史聊天不自动回填，也不修改历史回复。从部署本功能后开始收集；已有助手消息可在能校验关联运行时手动反馈。

## 验证

1. 单元测试验证收集分类：最终失败收集，正常无数据/权限不足/取消/澄清不收集，中间失败最终成功不误收集。
2. 验证同轮幂等、自动与手动来源补充、快照裁剪和脱敏、收集异常不影响聊天。
3. 接口测试验证菜单权限、租户隔离、管理详情不可跨租户、手动反馈不可跨用户。
4. 页面测试验证列表筛选分页、详情、加载/空/错误状态，以及“未解决”重复提交处理。
5. 执行 Agent、smart-boot 相关测试和 smart-web 构建，最后进行真实页面验收。

预计部署涉及 smart-agent、smart-boot 和 smart-web，以及 Agent 数据库迁移和业务库菜单登记。完成后提供实际重启清单及逐项人工测试步骤。
