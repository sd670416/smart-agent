# 8 个看板智能查询与比较分析设计

## 1. 目标

为经营、预算、应收、供应商、投标、库存、项目、甘特图 8 个看板提供自然语言查询和比较分析能力。查询必须遵循原看板的筛选项、默认行为和业务日期口径；比较分析必须对每一组筛选条件分别执行，再由后端计算差异。

权限只使用看板菜单权限。用户拥有某个看板菜单后，可以访问该看板的汇总、分析和下钻明细，不再额外检查项目成员权限或下钻业务菜单权限。

## 2. 原看板行为基线

| 看板 | 页面筛选项 | 默认行为 |
| --- | --- | --- |
| 经营 | 项目、费用日期范围 | 项目和日期为空，查询全部 |
| 预算 | 项目、费用日期范围 | 项目和日期为空，查询全部 |
| 应收 | 项目多选、费用日期范围 | 项目和日期为空，查询全部；图表默认 TOP 展示 |
| 供应商 | 项目多选、供应商多选、费用日期范围 | 筛选为空，查询全部 |
| 投标 | 审批状态、保证金类型（接口固定传值） | 默认 `approvalStatus=2`，保证金默认 `depositType=1` |
| 库存 | 仓库类型、仓库、材料、操作日期范围 | 筛选为空，查询全部；页面没有项目筛选 |
| 项目 | 项目 | 首次加载后自动选择项目列表第一个项目 |
| 甘特图 | 项目、任务名称、任务状态 | 项目为空查询全部；任务名和状态在前端过滤 |

## 3. 能力拆分

### 3.1 单组查询

工具：`board.query`

输入包括看板类型、指标、该看板允许的筛选项、分组维度、分页和排序。后端根据看板定义转换为原接口参数，执行汇总或明细查询，并返回中文指标名、单位、筛选条件、汇总值、分组结果和可下钻标识。

### 3.2 多组比较

工具：`board.compare`

输入包括同一看板、同一指标和两组或多组独立筛选条件。每组单独执行原接口查询，后端计算原始值、差额、增长率、共同项目、新增项目和减少项目。模型只解释结果，不自行计算金额或比例。

同一看板和同一指标是强约束；每组可以有不同项目、日期、状态或业务筛选。用户未提供完整分组条件时，返回需要补充的筛选项。

### 3.3 明细下钻

工具：`board.detail`

只接受查询或比较结果中产生的稳定 ID、项目 ID、合同 ID 等，不允许模型自行拼接未知 ID。明细查询继承本次看板权限和筛选快照。

## 4. 看板专属规则

- 经营、预算、应收、供应商、库存、投标的日期条件必须逐个映射到原服务实际使用的业务日期字段，不能统一命名为“统计日期”。
- 库存不增加页面没有的项目筛选；库存筛选使用仓库、材料和操作日期。
- 项目看板不默默采用页面第一个项目作为 AI 查询项目。用户未指定项目时，应提示选择项目；只有模拟页面默认行为的场景才允许记录默认项目。
- 甘特图的任务名称和状态属于前端过滤条件，后端查询接口只接收项目条件时，智能查询服务负责在结果集上执行同样的过滤。
- 应收的 TOP/全部是展示模式，不得当作数据范围过滤。AI 查询应返回完整汇总，并按用户要求返回排名或全部明细。
- 投标接口固定带审批状态，智能查询不得绕过该状态限制；用户明确要求其他审批状态时，需按接口能力提示不支持或提供可选状态。

## 5. 权限与安全

1. 根据看板稳定 `routeName` 优先、`routePath` 兼容匹配菜单。
2. 没有对应看板菜单时，返回“您当前没有该看板的访问权限，请联系管理员授权”。
3. 有看板菜单后，汇总、比较和明细统一放行，不再追加项目数据权限和业务菜单判断。
4. 多看板问题逐个校验权限，有权限的看板正常查询，无权限的看板单独返回提示。
5. 所有结果只输出业务字段，不输出系统字段、内部 SQL 或未授权的调试信息。

## 6. 默认、空值与异常

- 默认值沿用原页面：大多数看板筛选为空时查全部；投标使用固定审批状态；项目看板要求明确项目；甘特图查全部项目和任务。
- 单组查询默认返回汇总和前 20 条明细，继续查看时分页下钻。
- 无数据、权限不足、筛选项不支持、指标不明确分别返回不同的中文提示。
- 金额为空按无值展示，不在模型侧当作零参与计算；除数为零时增长率返回“无法计算”。
- 日期格式统一传递 `yyyy-MM-dd`，但每个指标保留自己的业务日期含义。

## 7. 上下文快照

每次查询和比较保存：看板、指标、筛选项、日期口径、分组名称、结果 ID 和权限校验结果。后续“和上个月比较”“只看第二组”“查看第 3 个项目”等问题从快照解析，不重新让模型猜测原条件。

## 8. 分阶段实施

1. 建立 8 个看板的指标、筛选项、接口和字段映射定义。
2. 实现 `board.query`，先覆盖各页面现有汇总和主要列表。
3. 实现 `board.compare`，复用单组查询并增加确定性差异计算。
4. 实现 `board.detail` 和上下文快照下钻。
5. 逐个看板联调，由用户分阶段构建和验证。

本阶段不执行构建或测试命令。
