# 项目档案聚合查询工具设计

## 1. 背景与目标

当前 `project.getOverview` 只返回项目名称、编号、状态、类型、预算和进度，无法覆盖项目档案页面中的完整业务信息。

本次新增只读工具 `project.getArchiveDetail`。用户查询某个项目的详情或完整档案时，工具一次返回项目基础信息、项目成员、七个业务页签和审批流程，并保证权限结果与原系统页面一致。

## 2. 范围

工具返回以下分区的全部可见明细：

1. 基础信息
2. 项目成员
3. 合同信息
4. 资金情况
5. 施工过程管理
6. 项目成本控制
7. 分包合同信息
8. 招投标信息
9. 保证金信息
10. 审批流程

现有 `project.getOverview`、`project.query`、项目档案页面及原业务接口保持不变。

## 3. 推荐架构

### 3.1 单次聚合调用

`smart-agent` 暴露 `project.getArchiveDetail` 工具，输入支持项目 ID、项目编号或项目名称。项目解析沿用现有可访问项目匹配逻辑。

工具通过签名内部请求调用 `smart-boot` 的项目档案聚合接口。`smart-boot` 依次调用项目档案页面已使用的业务服务，不直接访问无权限约束的业务 Mapper，也不调用公网服务。

选择单次聚合接口而不是多个模型工具，避免模型连续调用八至十次工具导致轮次过多、结果遗漏和 Token 浪费。

### 3.2 模块边界

- `smart-boot/smart-ai`：可信身份恢复、分区权限决策、聚合编排和响应 DTO。
- 原业务模块：继续负责项目档案各分区的数据查询和数据权限。
- `smart-agent`：项目标识解析、工具执行、结果大小保护和模型提示。
- `smart-web`：继续使用通用 Markdown 表格展示，不新增业务数据直连接口。

## 4. 权限设计

聚合查询采用三层权限校验。

### 4.1 项目访问权限

目标项目 ID 必须包含在 `smart-boot` 为当前登录用户生成并签名的可信项目范围内。校验失败时整个工具拒绝返回项目内容。

### 4.2 分区菜单权限

可信上下文增加项目档案各分区的规范化只读权限。权限由当前角色可访问菜单生成，不由模型或前端传入。

每个分区映射原系统对应菜单。用户无对应菜单权限时，该分区不返回汇总、数量或明细，避免通过统计值泄露不可见信息。

查询不额外要求按钮权限。新增、删除、修改、审批等按钮权限不被本只读工具使用。

### 4.3 明细数据权限

`smart-agent` 调用内部聚合接口时传递经过本地令牌验证的租户、用户、身份、角色和分区权限，并使用 HMAC 对内部请求签名。

`smart-boot` 验证签名后，在请求生命周期内恢复可信用户上下文，再调用原业务服务，使 MyBatis 数据权限拦截器按当前用户执行。禁止使用没有用户上下文的直连 Mapper 绕过数据权限。

用户只能获得同时满足以下条件的数据：

- 可访问目标项目；
- 可访问对应菜单；
- 满足该业务服务的数据维度规则。

超级管理员继续遵循原系统超级管理员规则。

## 5. 数据结构

聚合响应使用固定 DTO，不直接序列化业务实体。

```text
ProjectArchiveDetail
  projectId
  projectName
  sections[]
    key
    title
    status: AVAILABLE | EMPTY | FAILED
    summary
    items[]
```

无权限分区不进入 `sections`。有权限但无数据的分区使用 `EMPTY`。查询异常的分区使用 `FAILED` 和固定中文安全提示，不返回内部异常堆栈。

基础信息包含项目名称、编号、性质、类型、所属组织、所属公司、建设单位、施工单位、项目经理、状态、办公地址、详细地址、联营单位和项目概况。

审批流程包含节点名称、处理人、状态、开始时间、完成时间和审批意见。

附件只返回文件名称和系统内访问标识，不读取附件内容，也不把附件内容发送给外部模型。

## 6. 展示规则

智能助手按响应分区顺序生成中文标题和表格。每个分区返回全部可见明细，不进行人工分页或只取前几条。

无数据分区显示“暂无数据”。单元格保持单行，表格超出聊天区域时使用内部横向滚动。

字典值、组织、地区、人员及审批状态在 `smart-boot` 内转换为中文名称。聊天内容不展示字典编码或完整字典数据。

## 7. 异常与容量保护

- 单个分区失败不影响其他成功分区，失败分区显示“该部分暂时无法获取”。
- 项目不存在、名称不唯一或无项目权限时返回中文引导；候选项只来自用户可访问项目。
- 聚合响应设置安全大小上限。超过上限时明确提示数据量过大，不伪装成完整结果，也不静默截断。
- 工具保持只读，不触发写入、审批或业务状态变化。
- 调试与审计记录分区名称、状态、记录数和耗时，不记录敏感明细原文。

## 8. 兼容性

- `smart-boot` 使用 Java 8 语法。
- `smart-agent` 使用 Java 21。
- 保留现有工具和接口，避免影响原页面与已有智能助手查询。
- 内部接口继续使用短签名头，不转发长 Bearer Token。

## 9. 测试策略

- 完整权限用户获得全部分区。
- 部分菜单权限用户只获得允许分区。
- 同一分区内不可见明细被数据权限过滤。
- 超级管理员结果与原系统页面一致。
- 字典、组织、地区和人员返回中文名称。
- 分区异常时其他分区仍成功返回。
- 响应不包含租户 ID、删除标记、版本号、内部用户 ID 等系统字段。
- 项目不存在、名称不唯一、无权限和超限均返回中文安全提示。
- `smart-boot` Java 8 编译通过。
- `smart-agent` 工具、模型提示和聊天表格回归测试通过。
