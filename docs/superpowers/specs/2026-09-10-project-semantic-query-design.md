# 项目自然语言语义查询设计

## 1. 目标

让用户能够使用不同自然语言表达，对其有权访问的项目按业务字段自由组合筛选、排序、分组和聚合，同时复用现有工程系统的菜单权限、按钮权限和数据权限，不向模型开放任意 SQL。

第一版只支持项目资源。合同、材料、财务等资源在项目查询链路稳定后按相同协议逐个注册。

## 2. 已确认边界

- 查询权限沿用现有项目权限设计，不新增字段级权限。
- 用户有权访问某个项目时，该项目的全部业务字段均可查询。
- 系统字段不开放，包括租户、删除标记、流程实例、内部关联 ID、成员 ID、预留字段等。
- 默认返回 20 条明细，单次最多 100 条；分组结果最多 50 组。
- “今年创建/新增”按创建时间查询。
- “今年立项”在没有明确立项日期来源时必须追问用户，不得默认等同于创建时间。
- 查询只读；按钮权限继续用于后续增删改操作，不在本任务中扩展写能力。

## 3. 方案选择

采用结构化查询 DSL，并由 `smart-boot` 在数据库侧执行。

不采用以下方案：

- 不在 `smart-agent` 中直连工程业务数据库。
- 不允许模型生成或提交 SQL、表名、数据库列名。
- 不先拉取全部项目再由 Agent 内存筛选，以避免分页、统计和性能问题。

## 4. 调用链路

```text
smart-web 自然语言
  -> smart-agent ChatOrchestrator
  -> project.query
  -> ProjectQueryValidator
  -> SmartBootProjectBusinessClient
  -> smart-boot /internal/ai/tools/project-query
  -> ProjectQueryFieldRegistry
  -> BusProjectService / BusProjectDao
  -> MyBatis 租户和数据权限
  -> 结构化查询结果
  -> 模型生成中文回答
```

权限采用纵深校验：

1. `smart-agent` 仅向具有项目菜单权限的用户暴露 `project.query`。
2. 查询请求强制携带可信上下文中的项目 ID 范围，模型不能提供或覆盖该范围。
3. `smart-boot` 只接受经过内部签名的请求，并将可信项目范围加入查询条件。
4. 查询最终经过现有 MyBatis 租户和数据权限链路。

即使内部请求缺少 Web 登录线程上下文，可信项目 ID 条件也必须存在；项目范围为空时直接返回空结果，禁止退化为全表查询。

## 5. 查询协议

### 5.1 请求

```json
{
  "select": ["projectName", "projectCode", "projectStatus", "projectBudget"],
  "filter": {
    "logic": "and",
    "conditions": [
      {"field": "projectStatus", "operator": "eq", "value": "已立项"},
      {"field": "createDate", "operator": "between", "value": ["2026-01-01", "2026-12-31"]}
    ]
  },
  "groupBy": ["projectType"],
  "aggregations": [
    {"function": "count", "field": "projectId", "alias": "projectCount"},
    {"function": "sum", "field": "projectBudget", "alias": "budgetTotal"}
  ],
  "orderBy": [
    {"field": "projectCount", "direction": "desc"}
  ],
  "page": 1,
  "pageSize": 20
}
```

可信身份、租户、用户、权限和项目 ID 范围不属于模型参数，由 Agent 客户端在服务间调用时注入。

### 5.2 条件

条件树支持 `and`、`or` 和嵌套分组。操作符根据字段类型开放：

- 通用：`eq`、`ne`、`in`、`notIn`、`isNull`、`isNotNull`。
- 文本：`contains`、`startsWith`、`endsWith`。
- 数字和日期：`gt`、`gte`、`lt`、`lte`、`between`。

相同字段可以重复出现，以表达区间和复合条件。条件数量和嵌套深度受安全限额约束。

### 5.3 分组和聚合

业务字段可用于分组。聚合函数根据字段类型执行：

- 所有字段：`count`、`countDistinct`。
- 数字字段：`sum`、`avg`、`min`、`max`。
- 日期字段：`min`、`max`。

不适用于字段类型的运算返回明确的查询条件错误，不调用数据库。

### 5.4 响应

```json
{
  "mode": "aggregate",
  "page": 1,
  "pageSize": 20,
  "total": 9,
  "hasNext": false,
  "columns": [
    {"key": "projectType", "label": "项目类型", "type": "dictionary"},
    {"key": "projectCount", "label": "项目数量", "type": "number"}
  ],
  "rows": [
    {"projectType": "联营项目", "projectCount": 6}
  ],
  "appliedFilters": [
    {"field": "projectStatus", "label": "项目状态", "operator": "eq", "displayValue": "已立项"}
  ]
}
```

结果同时包含机器字段名和中文标签。字典只输出中文显示值给模型和聊天内容，内部字典编码仅用于查询执行。

## 6. 项目字段元数据

`smart-boot` 维护项目查询字段注册表，显式映射：

- DSL 业务字段名；
- 中文名称与自然语言别名；
- Java/数据库字段；
- 数据类型；
- 字典类型；
- 是否属于业务字段；
- 支持的操作符和聚合函数；
- 输出格式。

注册表只包含项目业务字段。禁止根据模型输入反射任意实体字段，禁止将用户提供的字段名直接拼入 SQL。

当前项目实体中的业务字段均应注册，包括项目名称、编号、性质、类型、规模、组织、公司、建设单位、总包单位、概况、地区、详细地址、资质、特殊要求、报备人、联营公司、联营联系人、联营电话、投标状态、施工合同登记状态、中标状态、项目状态、负责人和项目预算等。

创建时间和更新时间可以用于时间查询，但作为通用审计字段不直接暴露其底层系统含义；自然语言侧分别命名为“创建时间”和“更新时间”。

## 7. 字典和语义处理

- 字典字段通过现有 `AiDictionaryResolver` 将中文名称转换为真实值。
- 模型可以提交中文名称或真实字典值，但最终响应只展示中文名称。
- 字段别名由系统指令和字段元数据共同描述，例如“项目经理”“负责人”映射为 `personInChargeName`。
- 相对日期在 Agent 侧转换成明确起止时间，查询请求不得把“今年”“上个月”等模糊文本直接交给数据库。
- 缺少关键业务字段或存在多种合理口径时，Agent 返回澄清问题，不执行查询。

## 8. Agent 工具 Schema

当前模型网关只支持工具参数中的简单类型。`project.query` 需要数组、对象和嵌套条件，因此先扩展 `SupportedToolSchema`：

- 支持 object、array、items、properties、required、description 和 additionalProperties。
- 将同一结构用于发送给模型和本地校验，避免两套规则不一致。
- 拒绝未知字段、错误类型、超深嵌套和超大数组。
- 工具参数解析失败返回友好错误，不向聊天窗口输出参数 JSON。

## 9. smart-boot 执行设计

`smart-ai` 模块新增项目查询端点、请求 DTO、字段注册表、校验器和执行器。代码保持 Java 8 兼容，不使用 record、模式匹配、`List.of`、文本块或新版 switch 表达式。

执行器通过注册表将 DSL 转换为 MyBatis `QueryWrapper` 或受控 Mapper 查询：

- 字段和排序列只能来自注册表映射。
- 所有值使用参数绑定。
- 可信项目 ID 条件始终使用 `AND id IN (...)` 注入。
- 明细查询复用项目查询 Mapper。
- 聚合查询使用专用 Mapper，但仍经过租户拦截器和数据权限拦截器。
- 不使用 `${}` 接收任何用户或模型输入；如 Mapper 必须动态选择已注册列，只能使用服务端枚举生成的安全 SQL 片段。

## 10. 安全和资源限制

- 只允许单资源只读查询。
- 默认 20 条，单次最多 100 条，分组最多 50 组。
- 最大条件数 30，最大嵌套深度 3，最大排序字段数 5，最大分组字段数 5，最大聚合项数 10。
- 单次工具结果继续遵守 64KB 限制和 Agent 总超时。
- 项目可信范围为空时返回空结果。
- 字段、操作符或函数不支持时返回可理解的中文原因和可用范围。
- 查询计划、使用字段、筛选摘要、结果行数、耗时和错误码进入现有工具审计；不记录敏感请求头和密钥。

## 11. 错误与澄清

- 未知业务字段：说明未识别的条件并给出相近字段。
- 操作符与类型不匹配：说明该字段支持的查询方式。
- 字典名称不存在：提示可用字典名称，不返回内部字典 JSON。
- 日期语义不明确：生成澄清问题，不调用工具。
- 无菜单权限：返回无项目查询权限。
- 有菜单权限但结果为空：返回在当前数据权限范围内未找到数据。
- smart-boot 或模型异常：返回友好提示，并保留 runId/traceId 供调试。

## 12. 兼容与迁移

- 保留 `project.listAccessible`、`project.getOverview` 和 `project.getContracts`，不改变其接口行为。
- `project.query` 用于复杂筛选、统计和随机组合问题；已有工具继续服务明确的列表、单项目概况和合同查询。
- 工具相关性判断增加统计、筛选、排序和项目业务字段关键词，并结合会话历史。
- smart-web 继续使用现有 Markdown 表格展示，无需第一阶段新增独立查询构建页面。

## 13. 测试与验收

### Agent

- 嵌套工具 Schema 可以正常发送给模型并校验参数。
- 自然语言问题可以保留并调用 `project.query`。
- 未知字段、错误类型、超限和纯参数 JSON 均被拦截。
- 可信项目范围由上下文注入，模型无法覆盖。
- “查看更多”沿用同一查询条件并递增页码。

### smart-boot

- Java 8 编译通过。
- 每种字段类型和操作符均有单元测试。
- 字典中文值正确转换。
- AND、OR、嵌套条件、排序、分组和聚合结果正确。
- 空可信范围不会查询全表。
- 未注册字段不能进入 SQL。
- 明细、统计均受可信项目范围、租户和原数据权限约束。

### 端到端验收示例

- “查询今年创建且已经立项的联营项目数量。”
- “按所属组织统计各项目类型数量，数量从高到低。”
- “预算在一百万到五百万之间的项目有哪些？”
- “显示前 20 条，再看下一页。”
- “查询今年立项的项目。”应先澄清立项日期口径。
- 无项目菜单权限和无项目数据权限的用户不能获得项目数据。

## 14. 分步交付

1. 扩展 Agent 嵌套工具 Schema 支持。
2. 定义项目查询 DSL 和 Agent 侧校验。
3. 在 smart-boot 注册项目业务字段并完成明细筛选、排序。
4. 增加分组和聚合。
5. 接入 `project.query` 与上下文分页。
6. 完成权限、审计、中文错误和端到端回归。

每一步完成专项测试后暂停，由用户验证效果，再进入下一步。
